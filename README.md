# Pi Fleet

Pi Fleet управляет Raspberry Pi 4 в локальной сети. Панель показывает доступность SSH, собирает метрики по SSH, управляет питанием через PoE и может переустановить Raspberry Pi OS Lite или Ubuntu Server 24.04 LTS на зарегистрированную SD-карту.

## Вход в панель

Основная панель работает по адресу **https://192.168.10.248/**. Вход выполняется под пользователем `admin`. На действующем сервере пароль хранится в файле `/root/pi-fleet-ca/admin-password`, доступном администратору сервера. SSH-туннель для работы панели не нужен.

Если браузер ещё не доверяет сертификату панели, получите сертификат локального центра из доверенного источника. На действующем сервере его можно скачать с `http://192.168.10.248/pi-fleet-ca.crt`. Перед импортом сверьте SHA-256 с отпечатком, полученным в доверенной консоли сервера:

```sh
openssl x509 -in /srv/pi-reinstall/tls/ca.crt -noout -fingerprint -sha256
```

Импортируйте только публичный сертификат центра. Частные ключи, пароль панели, SNMP-учётные данные и образы с настройками пользователей должны оставаться на сервере.

## Добавление Raspberry Pi

Для карточки нужны имя для отображения и IPv4. Если питание подаётся через PoE, укажите физический порт от 1 до 24. Один порт можно назначить только одной Pi. Карточка без порта показывает «Питание управляется вручную». Имя, порт и CID карты можно изменить через «Редактировать карточку» после входа по HTTPS.

| Что нужно | Где добавить | Какие данные нужны |
| --- | --- | --- |
| Карточка и проверка доступности SSH | `http://192.168.10.248/` → «Добавить Raspberry Pi» | Имя, IP, порт при наличии PoE |
| CPU, RAM, сеть и диск | `https://192.168.10.248/` → «Подключить метрики» | Имя, IP, порт при наличии PoE, текущие SSH-логин и пароль, отпечаток ключа SSH-сервера Pi |
| Питание и перезагрузка | Карточка по HTTPS | Проверенная привязка IP → порт в конфигурации SNMP |
| Переустановка ОС | Карточка по HTTPS → «Настройки новой ОС» | Предварительно зарегистрированные Pi и SD-карта, включённая HTTP-загрузка EEPROM и доступный PoE-порт |

Если карточка уже есть, для подключения метрик укажите её существующий IP, раскройте «Данные SSH для метрик» и нажмите «Подключить метрики». Панель проверит SSH-ключ до отправки пароля. Пароль Pi используется один раз. Для последующего сбора метрик создаётся отдельный SSH-ключ, ограниченный командой чтения метрик. После переустановки этот ключ понадобится зарегистрировать заново.

### Как получить отпечаток ключа Pi

Отпечаток берётся у **SSH-сервера Raspberry Pi**. Это не пользовательский ключ с Mac и не отпечаток сертификата панели.

1. Откройте терминал **на самой Pi** через монитор и клавиатуру, BliKVM или уже доверенное SSH-подключение.
2. Выполните:

   ```sh
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

3. Скопируйте только часть, начинающуюся с `SHA256:`, до первого пробела. Например, из строки `256 SHA256:… root@raspberrypi (ED25519)` нужна только часть `SHA256:…`.
4. Вставьте её в поле **«Отпечаток ключа Pi»**. В соседних полях укажите логин и пароль от **текущей** ОС на Pi.

Чтобы посмотреть, какой ключ устройство предъявляет по сети, можно выполнить на Mac или Linux:

```sh
ssh-keyscan -T 5 -t ed25519 192.168.10.249 2>/dev/null | ssh-keygen -lf -
```

Этот запрос сам по себе не подтверждает подлинность ключа. Сверьте результат с доверенной консолью Pi до ввода пароля. После переустановки система обычно создаёт новый ключ хоста. Получите новый отпечаток и обновите регистрацию метрик.

## Регистрация SD-карты

На самой Raspberry Pi выполните:

```sh
cat /sys/block/mmcblk0/device/type
cat /sys/block/mmcblk0/device/cid
```

Первая команда должна показать `SD`. Вторая выводит CID из 32 шестнадцатеричных символов. Скопируйте его в поле **«CID SD-карты»** при добавлении Pi по HTTPS или в разделе **«Редактировать карточку»**. После замены карты обновите CID. Его сохранение в карточке позволяет установщику проверить носитель, но для запуска переустановки также нужны настройка EEPROM и регистрация самой Pi в обработчике.

## Переустановка из панели

1. Войдите по HTTPS и откройте карточку зарегистрированной Pi.
2. Раскройте **«Настройки новой ОС»**. Выберите **Raspberry Pi OS Lite 64-bit** или **Ubuntu Server 24.04 LTS 64-bit**.
3. Введите **имя хоста, логин и пароль для новой ОС**. Эти данные могут отличаться от текущего входа на Pi.
4. Подтвердите стирание SD и нажмите **«Переустановить ОС»**. Сервер соберёт персональный образ, опубликует подписанный установщик и перезапустит проверенный PoE-порт.
5. Следите за карточкой и, если доступен, экраном Pi. Статус **«Образ записан и проверен»** означает, что установщик перечитал образ с SD и сверил его хеш. Затем дождитесь загрузки ОС и проверьте вход, например `ssh ваш-логин@192.168.10.249`. Адрес после загрузки выдаёт DHCP, поэтому закрепите IP за MAC в DHCP заранее.

Если статус сообщает, что результат записи неизвестен, проверьте экран Pi перед отключением питания. Панель блокирует управление PoE во время активного задания.

### Если ОС сломалась и SSH недоступен

**Переустановка может работать без SSH и без старой ОС.** EEPROM Raspberry Pi запускает подписанный установщик по Ethernet до загрузки с SD. Установщик работает в RAM, сверяет MAC и CID карты и пишет образ на SD. Ему не нужны SSH-отпечаток, логин или пароль от сломанной ОС.

Это сработает, если Pi уже зарегистрирована для установки, в её EEPROM настроена HTTP-загрузка и доверенный ключ, сеть и PoE работают, а SD-карта имеет зарегистрированный CID и доступна для записи. Если поменяли карту, зарегистрируйте её новый CID. Если EEPROM настроена только на SD, сама карточка в панели сетевую загрузку не включит. Если карта физически неисправна, её нужно заменить. Без SSH обычную карточку можно добавить, а подключить расширенные метрики получится после восстановления системы.

Текущий обработчик и сервис загрузки обслуживают **одну заранее зарегистрированную Pi**. В действующей установке это `192.168.10.249`, порт 19. Добавление карточек других Pi не включает для них переустановку. Для нескольких Pi нужен отдельный шаг настройки сервиса загрузки и обработчика, чтобы они выбирали подходящий комплект по устройству.

## Первая установка на новую Raspberry Pi 4

На Pi с чистой SD-картой можно установить ОС. Для первой настройки доступны два пути.

- **Быстрый старт с Raspberry Pi Imager.** Подключите SD-карту к компьютеру, выберите Raspberry Pi 4 и нужную ОС, задайте пользователя и включите SSH в настройках Imager. Запишите карту, вставьте её в Pi и загрузите устройство по проводной сети. Этот вариант подходит для заводской платы, которой Pi Fleet ещё не управляет. [Установка ОС на Raspberry Pi](https://www.raspberrypi.com/documentation/computers/getting-started.html)
- **Первая запись через Pi Fleet.** Старая ОС на целевой SD-карте не нужна. Плата должна заранее уметь загружать подписанный установщик по HTTP. Для первоначальной настройки EEPROM проще загрузить Pi с временной карты, записанной через Imager. [HTTP-загрузка и ключи EEPROM](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#http-boot)

Порядок подготовки к Pi Fleet:

1. Загрузите временную ОС и подключите Ethernet. Проверьте, что DHCP выдаёт ожидаемый IP. Закрепите его за MAC, чтобы EEPROM и установленная ОС использовали тот же адрес.
2. Настройте EEPROM на HTTP → SD, укажите адрес загрузочного сервера, порт 8083, путь `/boot` и открытый ключ подписи Pi Fleet. Проверьте старт подписанного RAM-образа без записи на SD.
3. Добавьте карточку по HTTPS с именем и IP. Укажите проверенный порт, если Pi питается через PoE. Для платы с ручным питанием можно вести карточку, но текущий запуск переустановки требует PoE.
4. Получите CID именно **целевой** SD-карты и внесите его в карточку. Если для настройки использовалась другая карта, получите CID целевой карты в SD-слоте другой работающей Pi с системой на отдельном носителе. Также можно временно записать ОС на саму целевую карту, загрузить её и считать CID.
5. Зарегистрируйте Pi в обработчике и настройте выдачу загрузочного образа для её IP. В текущем развёртывании переустановка обслуживает одну Pi на порту 19. Для параллельного управления несколькими Pi потребуется расширить обработчик. После настройки выберите ОС на карточке и запустите установку.

## PoE

Кнопки **«Вкл»**, **«Выкл»** и **«Аппаратная перезагрузка»** доступны после входа по HTTPS и проверки привязки IP к порту. Аппаратная перезагрузка отключает и снова включает питание на том же порту.

На совместимом коммутаторе создайте отдельного пользователя SNMPv3 с уровнем `authPriv`. Разрешите читать POWER-ETHERNET-MIB и записывать только проверенные экземпляры `pethPsePortAdminEnable`. В веб-форме HP V1910 OID вводятся без начальной точки. Например, проверенный экземпляр для порта 19 — `1.3.6.1.2.1.105.1.1.1.3.1.19`.

В каталоге `FLEET_SWITCH_CONFIG` (по умолчанию `/srv/pi-reinstall/switch`) разместите `snmp.conf` с параметрами `defSecurityName`, `defAuthType`, `defAuthPassphrase`, `defPrivType` и `defPrivPassphrase`. Дайте контейнеру доступ на чтение через GID 10001. Пример `switch.json`:

```json
{
  "address": "10.178.57.3",
  "allow_write": false,
  "ports": {
    "192.168.10.249": {"number": 19, "group": 1, "index": 19}
  }
}
```

Задайте `allow_write: true` после проверки соответствия физического порта индексу SNMP и права записи. При изменении `switch.json` перезапустите контейнер панели.

## Развёртывание на Linux

1. Скопируйте `.env.example` в `.env` и задайте адрес панели, подсеть, IP тестовой Pi и пути к данным. Создайте каталог `FLEET_STATE` и его подкаталог `jobs` с владельцем UID 10001. Создайте каталоги `boot` и `images` внутри `FLEET_BOOT_FILES`.
2. В `FLEET_TLS_DIR` (по умолчанию `/srv/pi-reinstall/tls`) разместите `server.crt`, `server.key`, `ca.crt` и `auth.sha256`. Сертификат сервера должен содержать IP панели в SAN. В `auth.sha256` запишите SHA-256 строки `admin:<ваш случайный пароль>` без перевода строки. Частный ключ сервера и файл хеша должны быть доступны контейнеру через GID 10001, без доступа для остальных пользователей. Ключ центра сертификации храните отдельно.
3. Запустите `docker compose up -d --build`. Порты 80 и 443 используются панелью, 8083 — HTTP-сервисом сетевой загрузки.
4. Для установки подготовьте на сервере `/opt/pi-reinstall/build` с файлами загрузочного раздела Pi 4, ARM64 BusyBox, его библиотеками, `rpi-eeprom-digest` и закрытым ключом подписи. Установите `dosfstools`, `cpio`, `xz-utils`, `device-tree-compiler`, `snmp`, `openssl` и системные инструменты `losetup`, `mount` и `udevadm`. В EEPROM Pi установите соответствующий открытый ключ и задайте HTTP-сервер, порт 8083, путь `/boot` и порядок загрузки HTTP → SD. Сначала проверьте сеть подписанным RAM-образом без записи.
5. Поместите проверенные исходные образы в `/opt/pi-reinstall/images` под именами `raspios-lite-arm64.img.xz` и `ubuntu-server-24.04.img.xz`. После сверки SHA-256 создайте файлы `raspios-lite-arm64.ready` и `ubuntu-server-24.04.ready` в каталоге конфигурации коммутатора. Панель показывает в форме только готовые образы. [Образы Raspberry Pi OS](https://www.raspberrypi.com/software/operating-systems/) · [Ubuntu для Raspberry Pi](https://ubuntu.com/hardware/docs/boards/how-to/ubuntu_supported/raspberry-pi/)
6. В `/opt/pi-reinstall/install-device.json` запишите `ip`, `server`, `prefix`, `port`, `mac` и `max_payload_bytes`. Значение `max_payload_bytes` — допустимый объём сжатого образа в RAM с запасом для ядра и установщика. MAC и CID узнайте на Pi:

   ```sh
   cat /sys/class/net/eth0/address
   cat /sys/block/mmcblk0/device/type
   cat /sys/block/mmcblk0/device/cid
   ```

   Убедитесь, что тип носителя — `SD`, и сохраните CID в карточке через HTTPS. IP должен совпадать в карточке, настройках Compose и записи обработчика. Обработчик также требует проверенную привязку PoE и право переключения.
7. Разместите `reinstall.py`, `poe.py`, `build-probe.sh` и `install-sd.sh` в `/opt/pi-reinstall`. Установите `pi-fleet-reinstall.service` и `pi-fleet-reinstall.timer` в `/etc/systemd/system/`, выполните `systemctl daemon-reload` и `systemctl enable --now pi-fleet-reinstall.timer`. Журнал установки доступен через `journalctl -u pi-fleet-reinstall.service`.

Обработчик в текущей версии использует `/opt/pi-reinstall` и `/srv/pi-reinstall` напрямую. При переносе установки держите эти пути согласованными с Compose и конфигурацией службы.
