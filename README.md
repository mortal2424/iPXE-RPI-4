# Pi Fleet

Pi Fleet управляет Raspberry Pi 4 в локальной сети. Панель показывает доступность SSH, собирает метрики по SSH, управляет питанием через PoE и может переустановить Raspberry Pi OS Lite или Ubuntu Server 24.04 LTS на зарегистрированную SD-карту.

## Вход в панель

Откройте HTTPS-адрес своего развёртывания и войдите как `admin` с паролем, заданным при установке. В примерах ниже сервер использует `192.0.2.10`, Raspberry Pi — `192.0.2.20`, а домен панели — `fleet.example.com`. Замените эти демонстрационные значения реальными адресами своей сети.

Если используется локальный центр сертификации, передайте его публичный сертификат на клиент через доверенный канал. Перед импортом сверьте SHA-256 с отпечатком на сервере:

```sh
openssl x509 -in /srv/pi-reinstall/tls/ca.crt -noout -fingerprint -sha256
```

Импортируйте только публичный сертификат центра. Частные ключи, пароль панели, SNMP-учётные данные и образы с настройками пользователей должны оставаться на сервере.

## Добавление Raspberry Pi

Для карточки нужны имя для отображения и IPv4. Если питание подаётся через PoE, укажите физический порт от 1 до 24. Один порт можно назначить только одной Pi. Карточка без порта показывает «Питание управляется вручную». Имя, порт и CID карты можно изменить через «Редактировать карточку» после входа по HTTPS.

| Что нужно | Где добавить | Какие данные нужны |
| --- | --- | --- |
| Карточка и проверка доступности SSH | `https://fleet.example.com/` → «+ Добавить Pi» | Имя, IP, порт при наличии PoE |
| CPU, RAM, сеть и диск | `https://fleet.example.com/` → «+ Добавить Pi» | Имя, IP, порт при наличии PoE, текущие SSH-логин и пароль, отпечаток ключа SSH-сервера Pi |
| Питание и перезагрузка | Карточка по HTTPS | Проверенная привязка IP → порт в конфигурации SNMP |
| Переустановка ОС | Карточка по HTTPS → «Настройки новой ОС» | Предварительно зарегистрированные Pi и SD-карта, включённая HTTP-загрузка EEPROM |

В форме добавления заполните все три поля SSH, чтобы сразу подключить метрики, или оставьте их пустыми для карточки с проверкой доступности. Для существующей карточки откройте «Настройки» → «Доступ SSH и метрики». Панель проверяет отпечаток до отправки пароля и создаёт отдельный ключ, ограниченный чтением метрик.

После успешной переустановки из панели установщик получает новый SSH-отпечаток на напрямую подключённой загрузочной сети и сверяет MAC с регистрацией Pi. Панель в течение часа пробует подключиться с логином и зашифрованным паролем из формы установки. При успехе она обновляет привязку SSH и удаляет временную запись. Для переустановок, сделанных вне панели, можно указать текущие данные вручную в настройках карточки.

`FLEET_NETWORK` задаёт загрузочную подсеть. Для карточек и SSH-мониторинга в других подсетях задайте их списком через запятую в `FLEET_MANAGEMENT_NETWORKS`.

### Как получить отпечаток ключа Pi

Отпечаток берётся у **SSH-сервера Raspberry Pi**. Это не пользовательский ключ с Mac и не отпечаток сертификата панели.

1. Откройте терминал **на самой Pi** через монитор и клавиатуру, BliKVM или уже доверенное SSH-подключение.
2. Выполните:

   ```sh
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

3. Скопируйте только часть, начинающуюся с `SHA256:`, до первого пробела. Например, из строки `256 SHA256:… root@raspberrypi (ED25519)` нужна только часть `SHA256:…`.
4. Вставьте её в поле **«Отпечаток ключа Pi»**. В соседних полях укажите логин и пароль от **текущей** ОС на Pi.

Чтобы посмотреть, какой ключ устройство предъявляет по сети, можно выполнить на Mac или Linux:

```sh
ssh-keyscan -T 5 -t ed25519 192.0.2.20 2>/dev/null | ssh-keygen -lf -
```

Этот запрос сам по себе не подтверждает подлинность ключа. Сверьте результат с доверенной консолью Pi до ввода пароля. При ручной переустановке получите новый отпечаток и обновите доступ SSH в карточке.

## Настройка EEPROM из панели

При подключении метрик по HTTPS данные SSH автоматически сохраняются для управления этой Pi. Если карточка создана старой версией и пароль не сохранён, откройте в ней **«Доступ SSH для управления»** и введите только текущий пароль; логин и отпечаток используются из существующего подключения, новая карточка не создаётся. Используйте текущие логин, пароль и проверенный SSH-отпечаток Pi. Откройте **«Настроить EEPROM»** на карточке. Панель использует сохранённое подключение. Для чтения конфигурации достаточно SSH, для записи той же учётной записи нужны права `sudo`. После переустановки снова подключите метрики с новым отпечатком и паролем.

Нажмите **«Настроить EEPROM и перезагрузить»**. Панель сохраняет резервную копию текущей конфигурации на Pi в `/var/lib/pi-fleet-eeprom`, добавляет публичный ключ подписи и ставит обновление в очередь. Выберите порядок загрузки. Для переустановки из панели выберите HTTP → SD, адрес HTTP-сервера берётся из адреса панели, порт — 8083, путь — `/boot`. После подготовки Pi автоматически перезагрузится штатно примерно через 10 секунд. Результат подготовки или ошибка появятся во всплывающем окне. Кнопка **«Показать текущие настройки»** читает версию и конфигурацию загрузчика через SSH без изменений. Её можно использовать после перезагрузки, чтобы проверить применённый порядок.

Для формы нужен работающий SSH с паролем и утилиты `vcgencmd`, `rpi-eeprom-config`, `rpi-eeprom-update` на Pi. Файл установленной версии загрузчика должен присутствовать в пакете `rpi-eeprom`. Для специальной конфигурации EEPROM потребуется ручная проверка. Перед применением можно отменить ожидающее обновление командой `sudo rpi-eeprom-update -r`.

На сервере разместите **публичный** ключ подписи в `FLEET_SWITCH_CONFIG/eeprom-public.pem`. Для сохранения SSH-доступа положите ключ Fernet в `FLEET_TLS_DIR/ssh-credentials.key`. Дайте контейнеру доступ на чтение через GID 10001 и храните ключ отдельно от резервной копии SQLite.  Подготовка EEPROM на новой Pi ещё не регистрирует её в обработчике переустановки.

## Регистрация SD-карты

На самой Raspberry Pi выполните:

```sh
cat /sys/block/mmcblk0/device/type
cat /sys/block/mmcblk0/device/cid
```

Первая команда должна показать `SD`. Вторая выводит CID из 32 шестнадцатеричных символов. Скопируйте его в поле **«CID SD-карты»** при добавлении Pi по HTTPS или в разделе **«Редактировать карточку»**. После замены карты обновите CID. Его сохранение в карточке позволяет установщику проверить носитель, но для запуска переустановки также нужны настройка EEPROM и регистрация самой Pi в обработчике.

## Переустановка из панели

1. Войдите по HTTPS и откройте карточку зарегистрированной Pi.
2. Раскройте **«Настройки новой ОС»**. Выберите **Raspberry Pi OS Lite 64-bit** или **Ubuntu Server 24.04 LTS 64-bit**.
3. Введите **имя хоста, логин и пароль для новой ОС**. Эти данные могут отличаться от текущего входа на Pi.
4. Подтвердите стирание SD и нажмите **«Переустановить ОС»**. Сервер соберёт персональный образ и опубликует подписанный установщик. Панель отправит команду перезагрузки через сохранённый SSH-доступ. Если это не удастся, она попробует перезапустить питание через проверенный PoE-порт, если он указан.
5. Следите за карточкой и, если доступен, экраном Pi. Статус **«Образ записан и проверен»** означает, что установщик перечитал образ с SD и сверил его хеш. Затем дождитесь загрузки ОС и проверьте вход, например `ssh ваш-логин@192.0.2.20`. Если выбран DHCP, заранее закрепите IP за MAC на DHCP-сервере. При статическом режиме новая ОС использует адрес из карточки.

Если карточка показывает «Установщик готов. Сейчас выключите и снова включите питание Pi вручную», перезапустите питание. На загрузку установщика отводится до 10 минут с момента готовности образа. Если время истекло, запустите переустановку заново.

Если статус сообщает, что результат записи неизвестен, проверьте экран Pi перед отключением питания. Панель блокирует управление PoE во время активного задания.

### Если ОС сломалась и SSH недоступен

**Переустановка может работать без SSH и без старой ОС.** EEPROM Raspberry Pi запускает подписанный установщик по Ethernet до загрузки с SD. Установщик работает в RAM, сверяет MAC и CID карты и пишет образ на SD. Ему не нужны SSH-отпечаток, логин или пароль от сломанной ОС.

Это сработает, если Pi уже зарегистрирована для установки, в её EEPROM настроена HTTP-загрузка и доверенный ключ, сеть работает и Pi можно перезапустить вручную или через PoE, а SD-карта имеет зарегистрированный CID и доступна для записи. Если поменяли карту, зарегистрируйте её новый CID. Если EEPROM настроена только на SD, сама карточка в панели сетевую загрузку не включит. Если карта физически неисправна, её нужно заменить. Без SSH обычную карточку можно добавить, а подключить расширенные метрики получится после восстановления системы.

Обработчик обслуживает зарегистрированные Pi по очереди: одновременно выполняется одна переустановка. После настройки EEPROM нажмите в карточке **«Проверить готовность к переустановке»**. Панель через сохранённый SSH-доступ прочитает Ethernet MAC, CID карты и объём RAM, проверит настройки HTTP-загрузки и сохранит привязку автоматически. Пустой CID заполнится сам; несовпадающий CID вызовет ошибку. Затем откроется выбор ОС. Для старой карточки без сохранённого пароля дополните доступ через раздел «Доступ SSH для управления» прямо в карточке. Если проверка просит настроить EEPROM, примените «Сеть HTTP → SD», дождитесь перезагрузки и повторите проверку. SSH нужен для первичной подготовки; зарегистрированный сетевой установщик работает независимо от установленной ОС. Для Pi в другой подсети задайте маршрут через «Настройки панели».

## Первая установка на новую Raspberry Pi 4

На Pi с чистой SD-картой можно установить ОС. Для первой настройки доступны два пути.

- **Быстрый старт с Raspberry Pi Imager.** Подключите SD-карту к компьютеру, выберите Raspberry Pi 4 и нужную ОС, задайте пользователя и включите SSH в настройках Imager. Запишите карту, вставьте её в Pi и загрузите устройство по проводной сети. Этот вариант подходит для заводской платы, которой Pi Fleet ещё не управляет. [Установка ОС на Raspberry Pi](https://www.raspberrypi.com/documentation/computers/getting-started.html)
- **Первая запись через Pi Fleet.** Старая ОС на целевой SD-карте не нужна. Плата должна заранее уметь загружать подписанный установщик по HTTP. Для первоначальной настройки EEPROM проще загрузить Pi с временной карты, записанной через Imager. [HTTP-загрузка и ключи EEPROM](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#http-boot)

Порядок подготовки к Pi Fleet:

1. Загрузите временную ОС и подключите Ethernet. Проверьте, что DHCP выдаёт ожидаемый IP. Закрепите его за MAC, чтобы EEPROM и установленная ОС использовали тот же адрес.
2. Настройте EEPROM на HTTP → SD, укажите адрес загрузочного сервера, порт 8083, путь `/boot` и открытый ключ подписи Pi Fleet. Проверьте старт подписанного RAM-образа без записи на SD.
3. Добавьте карточку по HTTPS с именем и IP. Укажите проверенный порт, если Pi питается через PoE. Для платы с ручным питанием оставьте поле порта пустым.
4. Получите CID именно **целевой** SD-карты и внесите его в карточку. Если для настройки использовалась другая карта, получите CID целевой карты в SD-слоте другой работающей Pi с системой на отдельном носителе. Также можно временно записать ОС на саму целевую карту, загрузить её и считать CID.
5. Нажмите в карточке **«Проверить готовность к переустановке»**, затем выберите ОС, имя хоста, логин и пароль и подтвердите стирание карты. Ручная правка обработчика для каждой новой Pi не требуется.

## PoE

Кнопки **«Вкл»**, **«Выкл»** и **«Аппаратная перезагрузка»** доступны после входа по HTTPS и проверки привязки IP к порту. Аппаратная перезагрузка отключает и снова включает питание на том же порту.

На совместимом коммутаторе создайте отдельного пользователя SNMPv3 с уровнем `authPriv`. Разрешите читать POWER-ETHERNET-MIB и записывать только проверенные экземпляры `pethPsePortAdminEnable`. В веб-форме HP V1910 OID вводятся без начальной точки. Например, проверенный экземпляр для порта 19 — `1.3.6.1.2.1.105.1.1.1.3.1.19`.

В каталоге `FLEET_SWITCH_CONFIG` (по умолчанию `/srv/pi-reinstall/switch`) разместите `snmp.conf` с параметрами `defSecurityName`, `defAuthType`, `defAuthPassphrase`, `defPrivType` и `defPrivPassphrase`. Дайте контейнеру доступ на чтение через GID 10001. Пример `switch.json`:

```json
{
  "address": "192.0.2.2",
  "allow_write": false,
  "ports": {
    "192.0.2.20": {"number": 19, "group": 1, "index": 19}
  }
}
```

Задайте `allow_write: true` после проверки соответствия физического порта индексу SNMP и права записи. При изменении `switch.json` перезапустите контейнер панели.

### Регистрация PoE-порта из карточки

Укажите физический номер порта через **«Редактировать карточку»**. На коммутаторе разрешите пользователю Pi Fleet читать состояние этого порта и добавьте точный OID в **Write View**. Затем войдите по HTTPS, подтвердите, что кабель этой Pi подключён к указанному порту, и нажмите **«Зарегистрировать PoE-порт»**. Панель проверит право записи, отправив текущее значение PoE, и сохранит привязку в базе. После смены порта зарегистрируйте его заново.

Функция доступна при `"panel_port_registration": true` в `switch.json`. Включайте её только на коммутаторе, где SNMP-группа равна 1, а индекс PoE совпадает с физическим номером порта. Регистрация питания из карточки не добавляет Pi в обработчик переустановки.

## Развёртывание на Linux

1. Установите Docker Engine и Docker Compose v2. Скопируйте `.env.example` в `.env` и задайте адрес панели, подсеть, IP тестовой Pi и пути к данным. Создайте каталог `FLEET_STATE` и его подкаталог `jobs` с владельцем UID 10001. Создайте каталоги `boot` и `images` внутри `FLEET_BOOT_FILES`, а также `FLEET_SWITCH_CONFIG`, даже если PoE не используется.
2. В `FLEET_TLS_DIR` (по умолчанию `/srv/pi-reinstall/tls`) разместите `server.crt`, `server.key`, `ca.crt` и `auth.sha256`. Сертификат сервера должен содержать IP панели в SAN. В `auth.sha256` запишите SHA-256 строки `admin:<ваш случайный пароль>` без перевода строки. Частный ключ сервера и файл хеша должны быть доступны контейнеру через GID 10001, без доступа для остальных пользователей. Ключ центра сертификации храните отдельно. Для сохранения SSH-доступа создайте отдельный ключ Fernet и сохраните его в `ssh-credentials.key` в том же каталоге с правами `0640` и группой 10001. Например, ключ можно сгенерировать командой `openssl rand -base64 32 | tr '+/' '-_'`. Для настройки EEPROM поместите открытый ключ подписи загрузчика в `FLEET_SWITCH_CONFIG/eeprom-public.pem`.
3. Запустите `docker compose up -d --build`. Порты 80 и 443 используются панелью, 8083 — HTTP-сервисом сетевой загрузки.
4. Для установки подготовьте на сервере `/opt/pi-reinstall/build` с файлами загрузочного раздела Pi 4, ARM64 BusyBox, его библиотеками, `rpi-eeprom-digest` и закрытым ключом подписи. Установите `dosfstools`, `cpio`, `xz-utils`, `device-tree-compiler`, `snmp`, `openssl` и системные инструменты `losetup`, `mount` и `udevadm`. В EEPROM Pi установите соответствующий открытый ключ и задайте HTTP-сервер, порт 8083, путь `/boot` и порядок загрузки HTTP → SD. Сначала проверьте сеть подписанным RAM-образом без записи.
5. Поместите проверенные исходные образы в `/opt/pi-reinstall/images` под именами `raspios-lite-arm64.img.xz` и `ubuntu-server-24.04.img.xz`. После сверки SHA-256 создайте файлы `raspios-lite-arm64.ready` и `ubuntu-server-24.04.ready` в каталоге конфигурации коммутатора. Панель показывает в форме только готовые образы. [Образы Raspberry Pi OS](https://www.raspberrypi.com/software/operating-systems/) · [Ubuntu для Raspberry Pi](https://ubuntu.com/hardware/docs/boards/how-to/ubuntu_supported/raspberry-pi/)
6. В `/opt/pi-reinstall/install-device.json` запишите `ip`, `server`, `prefix`, `port`, `mac` и `max_payload_bytes`. Значение `max_payload_bytes` — допустимый объём сжатого образа в RAM с запасом для ядра и установщика. MAC и CID узнайте на Pi:

   ```sh
   cat /sys/class/net/eth0/address
   cat /sys/block/mmcblk0/device/type
   cat /sys/block/mmcblk0/device/cid
   ```

   Убедитесь, что тип носителя — `SD`, и сохраните CID в карточке через HTTPS. IP должен совпадать в карточке, настройках Compose и записи обработчика.
7. Разместите `reinstall.py`, `poe.py`, `build-probe.sh` и `install-sd.sh` в `/opt/pi-reinstall`. Установите `pi-fleet-reinstall.service` и `pi-fleet-reinstall.timer` в `/etc/systemd/system/`, выполните `systemctl daemon-reload` и `systemctl enable --now pi-fleet-reinstall.timer`. Журнал установки доступен через `journalctl -u pi-fleet-reinstall.service`.

Обработчик в текущей версии использует `/opt/pi-reinstall` и `/srv/pi-reinstall` напрямую. При переносе установки держите эти пути согласованными с Compose и конфигурацией службы.


### Подключение существующей карточки и VNC

Если подключение метрик отсутствует, раздел «Доступ SSH для управления» в карточке запросит логин, пароль и проверенный отпечаток ключа текущей ОС. Он обновляет существующую карточку по IP, не создавая дубликат. После сохранения подключается сбор метрик, а форма ввода пароля исчезает. После успешной проверки готовности её кнопка также скрывается.

«Открыть VNC» по умолчанию открывает `vnc://IP:5900` в установленном VNC-клиенте. В «Редактировать карточку» можно задать другой VNC-адрес или HTTP(S)-адрес веб-консоли, например noVNC или BliKVM. Для локальной текстовой консоли рабочий стол не требуется: используйте кнопку «Установить VNC» в карточке. Для работы непосредственно в браузере нужен отдельный VNC WebSocket-шлюз, например noVNC.


### VNC настоящей локальной консоли

В карточке с сохранённым SSH-доступом откройте **«Установить VNC»**, задайте отдельный пароль ровно из 8 печатных ASCII-символов (ограничение VNC-аутентификации), подтвердите установку. Панель установит x11vnc, инструмент создания пароля и поддержку ввода. X-сервер, оконный менеджер и рабочий стол не устанавливаются. Установка требует доступной ОС, SSH, sudo и доступа Pi к репозиториям пакетов.

Служба `pi-fleet-vnc.service` показывает **реальную текстовую tty1** через `/dev/vcsa1`, а клавиатуру передаёт через `/dev/uinput`. При запуске переключает локальный монитор на tty1; экран и ввод общие с локальной консолью. После установки кнопка «Открыть VNC» ведёт на `vnc://IP:5909`. Подключайтесь клиентом с TLS/VeNCrypt, например TigerVNC, примите и проверьте сертификат сервера. Понадобится заданный VNC-пароль, затем обычный вход Linux, если tty1 показывает приглашение login. При активном firewall вручную разрешите TCP 5909 из нужной локальной сети. Пароль VNC хранится на Pi в файле доступа root, пароль SSH используется из карточки.

Это программный доступ после запуска Linux: при зависшем ядре, выключенном питании, EEPROM или переустановке ОС используйте BliKVM. Экран читается как текст, а не как HDMI-видео. Переключение на другие tty на физической клавиатуре может направить ввод uinput в другую активную консоль; вернитесь на tty1. Ввод x11vnc через uinput ориентирован на US-раскладку; кириллица и отдельные специальные клавиши могут работать с ограничениями. После переустановки ОС VNC нужно установить заново.

Диагностика: `systemctl status pi-fleet-vnc.service`, `journalctl -u pi-fleet-vnc.service`, `/var/log/pi-fleet-vnc-install.log`. Отключение: `sudo systemctl disable --now pi-fleet-vnc.service`. [Режим Linux Console в документации x11vnc](https://manpages.debian.org/testing/x11vnc/x11vnc.1.en.html).


### Статический IP при переустановке

В «Настройки новой ОС» по умолчанию выбран **«Статический IP из карточки»**. IP автоматически берётся из карточки и не меняется в форме установки. Укажите префикс (например `24`), шлюз в этой подсети и от 1 до 3 IPv4 DNS-серверов через пробел. Панель проверяет параметры и передаёт их обработчику вместе с конкретным заданием. При выборе DHCP статические поля отключаются.

Обработчик записывает `network-config` в загрузочный раздел образа до записи SD: для Raspberry Pi OS используется Netplan/NetworkManager, для Ubuntu Server — Netplan/networkd. Ethernet определяется по зарегистрированному MAC, поэтому названия `eth0` и `end0` не влияют на привязку. При статическом IPv4 DHCP для этого Ethernet отключён. Конфигурация действует с первой загрузки новой ОС; текущая работающая ОС сама по себе не перенастраивается.

В шапке откройте **«Настройки панели»**. Здесь можно изменить дополнительные подсети управления и переустановки, а также режим IPv4, префикс, шлюз и DNS по умолчанию. Значения сохраняются в базе панели и подставляются в новые формы переустановки. Для маршрутизируемой подсети используются её префикс и шлюз. DNS берётся из общих настроек, а при пустом значении используется шлюз этой подсети.

До первого сохранения панель читает исходные значения из `FLEET_MANAGEMENT_NETWORKS` и, если он есть, `network-defaults.json` в `FLEET_SWITCH_CONFIG`. Сохранённые настройки имеют приоритет. Во время активной переустановки изменение сетей заблокировано. IP сервера, основную сеть, домен, привязку портов Docker и TLS задаёт администратор сервера. Параметры SNMP находятся в каталоге конфигурации коммутатора.

Сохраните резервации адресов на DHCP-сервере или исключите эти адреса из динамической выдачи другим устройствам. EEPROM при сетевой загрузке всё ещё получает сетевые параметры от DHCP: статический адрес новой ОС не заменяет настройки DHCP для загрузчика. [Сеть cloud-init в Raspberry Pi OS](https://www.raspberrypi.com/news/cloud-init-on-raspberry-pi-os/).

### Компактные карточки и окна настроек

Кнопка **«+ Добавить Pi»** находится в шапке и открывает форму в модальном окне. На карточке остаются метрики, состояние и управление питанием, VNC и запуск переустановки. Кнопка **«Настройки»** открывает историю метрик, редактирование карточки, подключение SSH, EEPROM, проверку готовности и установку VNC. Параметры новой ОС открываются отдельным окном. Окна закрываются кнопкой × или клавишей Escape.

### Let’s Encrypt для частного адреса и домена

Для собственного домена можно использовать DNS-01. Пример ниже использует Selectel API v2: публичный IP сервера и открытие портов из интернета не требуются. Сам домен должен разрешаться в `192.0.2.10` для клиентов вашей сети. NS зоны должны быть публично доступны для проверки TXT-записей. [Проверка DNS-01](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge).

1. В `/opt/pi-reinstall/.env` укажите свой домен в `FLEET_DOMAIN` без кавычек. `FLEET_IP` задайте отдельно: HTTP-загрузчик и EEPROM используют IP независимо от домена панели.
2. Установите ACME-клиент через `ops/setup-acme.sh` на сервере. Он создаёт отдельное окружение `/opt/pi-fleet-acme`.
3. Скопируйте `ops/selectel.ini.example` в `/srv/pi-reinstall/acme/selectel.ini`, права `0600`, владелец root. Заполните номер аккаунта, имя проекта, имя и пароль сервисного пользователя Selectel с доступом к DNS API. Пароль со знаком `#` и другими INI-спецсимволами заключайте в кавычки: неэкранированный пароль Certbot может прочитать не полностью. Реальные реквизиты не храните в репозитории. [Формат реквизитов плагина](https://github.com/alxrem/certbot-dns-selectel-api-v2#credentials).
4. Разместите скрипты в `/opt/pi-reinstall/ops`, выдайте двум `.sh` права `0700` и запустите `/opt/pi-reinstall/ops/issue-letsencrypt.sh`. Скрипт выпуска использует регистрацию ACME без email; при необходимости укажите email в Certbot отдельно.
5. Deploy-hook проверяет сертификат для домена и соответствие ключа, помещает файлы `domain.crt` и `domain.key` в каталог TLS и перезапускает только контейнер панели. Для домена через SNI используется Let’s Encrypt, для прямого IP сохраняется прежний сертификат локального CA. Let’s Encrypt не удостоверяет частный IP; открывайте панель по домену для публично доверенного HTTPS.
6. Установите `ops/pi-fleet-acme-renew.service` и `.timer` в `/etc/systemd/system`, затем `systemctl daemon-reload` и `systemctl enable --now pi-fleet-acme-renew.timer`. Проверка выполняется дважды в сутки с задержкой; Certbot продлевает выпущенные сертификаты. После выпуска проверьте `/opt/pi-fleet-acme/bin/certbot renew --dry-run --no-random-sleep-on-renew`.

Таймер и плагин сами по себе не означают, что сертификат уже выпущен: для первого выпуска нужны заполненные реквизиты и успешная DNS-проверка. Журналы: `journalctl -u pi-fleet-acme-renew.service`, `/var/log/letsencrypt/letsencrypt.log`.

Используемая версия DNS-плагина — `certbot-dns-selectel-api-v2==0.3.0`; setup устанавливает недостающую `zope.interface==8.7` и исправляет обработку структурированных ошибок API скриптом `ops/patch-selectel-plugin.py`.

В шапке панели откройте **«Настройки панели» → «Дополнительные сети переустановки»**. Для дополнительной сети укажите CIDR и шлюз в одной строке, например `198.51.100.0/24 198.51.100.1`. Основная загрузочная сеть доступна по умолчанию. Для каждой дополнительной сети нужны DHCP для сетевой загрузки EEPROM, маршрутизация в обе стороны до загрузочного сервера и доступ к его TCP-порту 8083. Оставьте загрузочный IP Pi совпадающим с адресом карточки. После установки в маршрутизируемой сети обновите SSH-отпечаток в настройках карточки.

### CM4 Lite с SD-картой

Pi Fleet поддерживает переустановку Raspberry Pi Compute Module 4 Lite на SD-карту. Положите в каталог сборки `/opt/pi-reinstall/build` файл `bcm2711-rpi-cm4.dtb` от той же версии ядра, что и `kernel8.img`. Установщик сверяет модель платы, тип носителя SD, CID и MAC перед записью.

Подготовьте EEPROM CM4 через панель в режиме self-update или через `rpiboot` с HTTP первым в порядке загрузки (`BOOT_ORDER=0xf17`), адресом загрузочного сервера в `HTTP_HOST`, портом `8083`, путём `/boot` и публичным ключом Pi Fleet. Затем в карточке выполните **«Проверить готовность к переустановке»**. Если CM4 находится в другой подсети, добавьте её в **«Настройки панели» → «Дополнительные сети переустановки»** и обеспечьте DHCP и доступ к серверу на TCP 8083. Запись на eMMC и NVMe не поддерживается. [Настройка загрузчика Compute Module](https://www.raspberrypi.com/documentation/computers/compute-module.html#update-the-bootloader).

На CM4 Lite в настройках EEPROM можно сначала нажать **«Проверить возможность записи»**. Панель соберёт образ во временном каталоге Pi. Для записи нужны локальный загрузочный раздел SD, совместимая текущая версия EEPROM и `ENABLE_SELF_UPDATE=1`. Если исходного образа текущей версии нет в пакете `rpi-eeprom`, администратор может положить оригинальный образ Raspberry Pi в `/var/lib/pi-fleet-eeprom/firmware/pieeprom-YYYY-MM-DD.bin` на самой Pi. Для применения подтвердите перезагрузку и нажмите **«Настроить EEPROM и перезагрузить»**. После загрузки проверьте фактические значения кнопкой **«Показать текущие настройки»**. Во время записи EEPROM не отключайте питание.
